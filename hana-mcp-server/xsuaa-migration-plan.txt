Plan: Replace Static Bearer Token with SAP BTP XSUAA JWT Auth

Context

The current MCP server uses a single shared static Bearer token (MCP_API_TOKEN). Anyone who possesses the token can call the API — there is no per-user identity, no revocation, and no role-based access control. The goal is to replace this with SAP BTP XSUAA OAuth2 so every caller must present a valid JWT issued by SAP ID Service, and only users assigned the HanaMcpAccess role can connect.

Requirements confirmed:
- Users: SAP BTP users authenticated via SAP ID Service (standard XSUAA)
- XSUAA always enforced — no dev bypass, even locally
- Access control: role-based via XSUAA scope $XSAPPNAME.access

---

Files to Change

1. NEW — hana-mcp-server/xs-security.json

XSUAA application security descriptor. Needed by cf create-service.

{
  "xsappname": "hana-mcp-bdc",
  "tenant-mode": "dedicated",
  "scopes": [
    { "name": "$XSAPPNAME.access", "description": "Permission to call HANA MCP tools" }
  ],
  "role-templates": [
    { "name": "HanaMcpAccess", "scope-references": ["$XSAPPNAME.access"] }
  ],
  "role-collections": [
    {
      "name": "HanaMcpAccessCollection",
      "description": "Users who may call the HANA MCP server",
      "role-template-references": ["$XSAPPNAME.HanaMcpAccess"]
    }
  ]
}

2. requirements.txt

Add sap-xssec>=3.6.0,<5.0.0.

3. manifest.yml

Add under the app:

  services:
    - hana-mcp-xsuaa

This binds the XSUAA instance and injects its credentials into VCAP_SERVICES automatically.

4. hana_mcp_server.py — main changes

Imports — add: asyncio, logging, from urllib.parse import urlparse, from sap import xssec. Add logger = logging.getLogger(__name__).

Remove — API_TOKEN = os.getenv("MCP_API_TOKEN", "") and the entire SecurityMiddleware class.

Add _load_uaa_credentials() function — reads XSUAA credentials from:
- VCAP_SERVICES (CF, injected automatically by the service binding)
- Or individual env vars XSUAA_URL, XSUAA_CLIENT_ID, XSUAA_CLIENT_SECRET, XSUAA_APP_NAME (local dev)
- Raises RuntimeError if neither is configured

Add _send_json_error(send, status, message) helper — returns JSON error bodies for 401/403/500.

Replace SecurityMiddleware with XSUAAMiddleware — pure ASGI class that:
1. Extracts Bearer JWT from Authorization header -> 401 if missing
2. Validates via await asyncio.to_thread(xssec.create_security_context, token, creds) -> 401 if invalid/expired
3. Calls security_ctx.check_local_scope("access") -> 403 if scope absent
4. Rewrites Host header to localhost (CF proxy fix — this was documented but never implemented in the old middleware)
5. Passes patched scope to the app

Note on check_local_scope: BTP appends a technical suffix at runtime (hana-mcp-bdc!t12345). check_local_scope("access") uses the xsappname from VCAP_SERVICES (which already includes the suffix) so it resolves correctly. check_scope("hana-mcp-bdc.access") would always fail.

Update main block — replace SecurityMiddleware(asgi_app, token=API_TOKEN) with XSUAAMiddleware(asgi_app). Update startup logs to show XSUAA URL and appname instead of token status.

5. env.example

Remove MCP_API_TOKEN. Add XSUAA env vars with instructions for obtaining a service key and a test token (password grant and client credentials examples).

---

CF Setup Commands (run once before cf push)

  # Create the XSUAA service instance
  cf create-service xsuaa application hana-mcp-xsuaa -c xs-security.json

  # Verify creation
  cf service hana-mcp-xsuaa

  # Deploy (binds the service, injects VCAP_SERVICES, installs requirements.txt)
  cf push

  # Confirm binding
  cf env hana-mcp-bdc        # should show xsuaa under VCAP_SERVICES
  cf logs hana-mcp-bdc --recent    # should show "XSUAA auth : ACTIVE"

BTP Cockpit — assign role to users (one-time per user):
- Subaccount -> Security -> Role Collections -> HanaMcpAccessCollection -> add user emails

Verification

Scenario                          | Expected result
----------------------------------|------------------------------------------------
No Authorization header           | 401 JSON: "missing or malformed"
Invalid / expired JWT             | 401 JSON: "invalid signature"
Valid JWT, no access scope        | 403 JSON: "lacks the HanaMcpAccess role"
Valid JWT + access scope          | 200, tools accessible
XSUAA vars missing at startup     | process stays up, every request returns 500

Getting a test token in Postman:
  POST <XSUAA_URL>/oauth/token
  Basic Auth: XSUAA_CLIENT_ID / XSUAA_CLIENT_SECRET
  Body (form): grant_type=password, username=<btp-email>, password=<btp-password>

Use the returned access_token as Bearer in subsequent MCP calls.
