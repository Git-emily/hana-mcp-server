BTP Deployment Guide — HANA MCP Server (XSUAA Auth)
====================================================

PREREQUISITES
-------------
- Local test passed (XSUAA service hana-mcp-xsuaa already exists in adoption-tools / DEV)
- CF CLI installed and logged in to adoption-tools / DEV space
- HANA connection details available


STEP 1 — Target the Correct Space
----------------------------------
  cf login -a https://api.cf.eu12.hana.ondemand.com --sso
  cf target -o adoption-tools -s DEV

Verify the XSUAA service is there:
  cf service hana-mcp-xsuaa   -> should show "create succeeded"


STEP 2 — Set HANA Secrets via cf set-env
-----------------------------------------
These are never stored in the manifest. Set them once:

  cf set-env hana-mcp-bdc HANA_HOST     your-real-hana-host.hanacloud.ondemand.com
  cf set-env hana-mcp-bdc HANA_USER     YOUR_HANA_USER
  cf set-env hana-mcp-bdc HANA_PASSWORD YOUR_HANA_PASSWORD
  cf set-env hana-mcp-bdc HANA_SCHEMA   BDC_ASSESSMENT

NOTE: MCP_API_TOKEN is no longer needed — do NOT set it.
      If it was set previously, remove it:
        cf unset-env hana-mcp-bdc MCP_API_TOKEN


STEP 3 — Deploy
----------------
Run from the project folder:

  cd "C:\Users\I517309\OneDrive - SAP SE\Analytics\Joule_Assessment\hana-mcp-server\hana-mcp-server"
  cf push

CF will automatically:
  - Install requirements.txt (including sap-xssec) via Python buildpack
  - Bind hana-mcp-xsuaa service and inject credentials into VCAP_SERVICES
  - Start the app on an assigned PORT


STEP 4 — Verify Deployment
----------------------------
Check app is running:
  cf app hana-mcp-bdc

Check XSUAA binding is present:
  cf env hana-mcp-bdc
  -> Look for "xsuaa" section under VCAP_SERVICES

Check startup logs:
  cf logs hana-mcp-bdc --recent
  -> Should show:
     [HANA MCP] XSUAA auth : ACTIVÉ  url=https://...
     [HANA MCP] XSUAA app  : hana-mcp-bdc!t...


STEP 5 — Assign Role to Users (if not already done)
-----------------------------------------------------
BTP Cockpit:
  Subaccount -> Security -> Role Collections -> HanaMcpAccessCollection
  -> Edit -> Users -> Add -> enter BTP email -> Save

Each user who needs access must be added here.


STEP 6 — Test on BTP with Postman
-----------------------------------
Get a fresh token (same as local test, Step 6 of local-test-guide.txt).

Then call the BTP URL instead of localhost:

Method : POST
URL    : https://hana-mcp-bdc.cfapps.eu12.hana.ondemand.com/mcp
Headers:
  Authorization : Bearer <access_token>
  Content-Type  : application/json
  Accept        : application/json, text/event-stream
Body (raw JSON):
  {
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2024-11-05",
      "capabilities": {},
      "clientInfo": { "name": "test", "version": "1.0" }
    }
  }

Then call a tool:
  {
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/call",
    "params": {
      "name": "get_schema_overview",
      "arguments": {}
    }
  }
  (Include mcp-session-id header from the initialize response)


EXPECTED RESULTS
----------------
Scenario                        | Expected Response
--------------------------------|------------------------------------------
Valid token + role assigned     | 200 OK
Valid token + role NOT assigned | 403 Forbidden
No token / wrong token          | 401 Unauthorized


DIFFERENCE vs LOCAL TEST
-------------------------
Local                          | BTP
-------------------------------|------------------------------------------
URL: http://localhost:8000/mcp | URL: https://hana-mcp-bdc.cfapps.eu12.hana.ondemand.com/mcp
XSUAA creds from .env          | XSUAA creds from VCAP_SERVICES (auto-injected)
HANA vars from .env            | HANA vars from cf set-env


UPDATING THE APP AFTER CODE CHANGES
-------------------------------------
Simply run cf push again from the project folder.
No need to recreate the XSUAA service or reset env vars — they persist.

  cf push
